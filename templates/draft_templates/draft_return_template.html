Confirmed Draft Return

#NEW —
{% comment %} Says which document this is and which it is not. A serial sold on an ordinary invoice is refused here and sent to the Sale Return screen, and the mirror holds there -- enforced in the database, not by this sentence. {% endcomment %}

This returns goods that were confirmed out of a draft — priced, invoiced and delivered — and are now coming back. Serials sold on an ordinary sale belong on the Sale Return screen. Returned units go back to free stock, not back to their reservation.

{% comment %} What this screen is NOT for. A reservation is not a sale -- no invoice, no balance, nothing ever left stock -- so there is no return to make, and the action that frees the unit lives on the draft itself. The database refuses it either way; this is so nobody has to learn that by being told no. {% endcomment %}

Still reserved and not yet confirmed? There is nothing to return — a draft raises no invoice and moves no stock. Open the draft on {% if features.draft_invoices.subs.drafts %}Draft Invoices{% else %}Draft Invoices{% endif %} and use Release Serials to put the unit back into free stock.

{% comment %} Read-only and filled from the first serial. The serial's sale decides the only party that may return it, so asking the operator to type it as well would only be a chance to get it wrong. {% endcomment %}
{% comment %} A real date, sent to the database and booked on that date -- unlike the older return screens, which stamp today's date whatever is picked. {% endcomment %}
